# 《中军帐》核心设定速查 (Project North Star)

> 本 skill 是 v0.2 设计蓝图的**压缩版权威参照**。目的：让你无需重读 248 行原文即可掌握全局。需要某子系统的细节规格时,转 `command-tent-systems`;写 C# 内核时,转 `command-tent-csharp`。

## 1. 游戏身份 (一句话)
单机 PVE、冷兵器、古代战争策略游戏。**核心 = 信息不对称**：你是中军帐里的孤独主帅,只能靠**滞后 / 残缺 / 失真的情报**指挥,**永远没有上帝视角**。乐趣来自"看不清却要决断"的揪心感。

## 2. 双世界模型 (整个项目的技术与体验主轴)
- **真相世界 (TruthWorld)** = 权威的实际战场状态(部队真实位置 / 兵力 / 意图…)。玩家战中**永远看不到**。
- **认知世界 (BeliefWorld)** = 玩家通过情报拼出的图景(沙盘上的"最后已知"标记 + 信息年龄 + 幽灵标记)。玩家**只操作这一层**。
- **传令系统 (CourierSystem)** = 两者之间的延迟 / 失真中介。情报从真相世界流向认知世界要花时间、会丢、会错;命令从认知世界流回也要花时间。
- 这条主轴在三层架构里**各复用一次**(尺度不同),且是 C# 引擎无关内核要实现的东西。

## 3. 四大设计支柱 (一切设计的自洽性检验标准)
- **① 迷雾即灵魂**：延迟 / 残缺 / 失真情报是灵魂本体,无一处给上帝视角。任何设计若给了上帝视角 = 违背支柱①。
- **② 中军帐 UI / 道具**：通过点击帐内实物(沙盘 / 令旗 / 文书堆 / 传令兵席…)行使指挥,强实景沉浸。
- **③ 等待是玩法**：你等情报时真相世界在动,每个空窗 = "再等一份情报 vs 现在就赌"。
- **④ 难度 = 信息丰度**：难度主要靠调"信息丰度"(延迟 / 丢失 / 残缺 / 失真率 / 提示有无)+ 少量数值,不靠堆敌人血量。

> 检验任何新提案时问：它强化了哪条支柱?有没有破坏支柱①(给上帝视角)?

## 4. 三层架构 (尺度不同,主轴相同)
- **生涯层 (Career)**：半线性将军生涯,多战役串成主线、关键处分支。核心元状态(声望 / 老兵 / 将领班子 / 皇恩 / SAN)**跨章节延续**。→ 完整层。
- **战略层 (Strategy)**：章节内的节点图战役,天数 / 回合制,完整对称迷雾,靠斥候带回延迟战略情报。→ 完整层。
- **战术层 (Tactical)**：20–30 分钟实时可暂停的单场战斗,核心延迟情报体验。→ **原型唯一焦点**。

## 5. 战术核心循环 (原型要验证的东西)
读滞后战报 → 拼图 → 下意图(结构化动词 + 基调) → 延迟送达 → 副将按"送达那刻的真实情况"解读执行 → 结果 → 战报延迟送回 → 看到过期结果 → 调整。

- 控制单位 = **部队 (Unit)**,非士兵。每方 3–4 支(左翼 / 中军 / 右翼 / 预备队),各由一名**副将 (Lieutenant)** 统领。
- 下意图 = 选部队 + **动词**(移动 / 攻击 / 据守 / 后撤) + 目标 + **基调**(谨慎 / 常规 / 激进 / 不惜代价 / 见机行事)。基调 = 给副将解读留的空间。
- **副将解读 = 第二层迷雾**:性格驱动同一意图的不同执行。

## 6. ⚠️ 范围红线 (最重要的纪律,别越界)
- **原型(里程碑一 / 二)只验证战术内核**:一场外部遭遇战的延迟情报是否「揪心、上头」。**内核不好玩,以上全部白搭**。
- **完整层(里程碑三 / 四)** 才有:战略层、生涯层、多轴压力失败系统、将领养成、造反线(造反线尤其属 stretch)。
- **原型唯一可早期试水的完整层机制**:`SAN↓ → 信息失真`(复用认知世界失真管线)。仍是 nice-to-have,非原型必需。
- 当用户在原型阶段讨论战略 / 生涯 / 多轴系统时,**温和提醒这属完整层**,除非用户明确在做前瞻设计。

## 7. 技术与美术决策 (已定)
- **技术栈**:C# **引擎无关内核**(纯 .NET 类库)实现真相 / 认知 / 传令 + xUnit 单测;里程碑二接 **Godot (C#)** 时整块复用,**零重写**。内核与引擎彻底分离 —— 内核**不得**依赖任何引擎 / 渲染 / 输入 API。
- **美术北极星**:原型 = 纯几何符号 / 棋子标记;战中 = 抽象沙盘(只见认知世界);**复盘** = 《全面战争》式战场可视化(完整层 / Godot)。**抽象 ↔ 电影感的反差**是核心呈现张力。
- 原型 UI(ASCII):一屏 = 文字沙盘(中心) + 战报队列 + 命令菜单 + 状态行(时间 / 天气 / 预备队)。

## 8. 协作约定 (跟这个项目工作时的默认行为)
- **语言**:设计概念用中文,代码标识符用英文,关键术语首次出现给中英对照(见 §10)。沿用用户偏好"英文技术术语 + 中文解释"。
- **设计记录 ≠ 开工指令**:讨论设计不等于要立刻写代码。何时动手是单独的决定,别擅自跳到实现。
- **守红线**:实现前先确认在原型范围内;别把完整层系统塞进原型。
- **务实直接**:范围 / 可行性给诚实判断,别画大饼。

## 9. 其它已定决策 (速查,细节转 systems skill)
- **战斗结算**:抽象 attrition,损耗 = f(兵种克制 × 地形 × 士气 × 体力 × 随机)。三角:枪克骑 / 骑克弓散 / 弓克步 / 盾抗远程。士气、体力 = 隐藏关键值。
- **情报失真四类**:延迟 / 丢失(纯沉默) / 残缺 / 失真,统一管线生成。
- **多轴压力失败**(完整层):5 主轴(士气 / 粮草 / 经费 / 皇恩 / SAN) + 伤亡计数器;结局由"哪条轴先被击穿"决定。
- **敌方 AI**:对称迷雾地基;原型 / 战术用 Utility AI,完整层战略叠 GOAP。性格 = 效用权重向量。
- **天气 / 地形**:双重作用(信息 + 战斗)。原型子集:平原 / 林地 / 河流 + 晴 / 雾 / 夜。天气由章节 / 难度设定,不在局内随机。
- **复盘**:战后认知 vs 真相对照回放,全图真相揭示,《全面战争》式可视化。

## 10. 中英术语对照表 (写代码 / 命名时的权威映射)
| 中文 | 代码标识符 (English) | 说明 |
|---|---|---|
| 真相世界 | `TruthWorld` | 权威实际战场状态 |
| 认知世界 | `BeliefWorld` | 玩家通过情报拼出的图景 |
| 传令系统 | `CourierSystem` | 真相→认知的延迟 / 失真中介 |
| 部队 | `Unit` | 控制单位(非士兵) |
| 副将 | `Lieutenant` | 统领部队、解读意图 |
| 意图 / 命令 | `Intent` / `Order` | 结构化动词 + 基调 |
| 动词 | `Verb` | 移动 `Move` / 攻击 `Attack` / 据守 `Hold` / 后撤 `Withdraw` |
| 基调 | `Tone` (或 `Posture`) | 谨慎 `Cautious` / 常规 `Normal` / 激进 `Aggressive` / 不惜代价 `AtAllCosts` / 见机行事 `UseJudgment` |
| 战报 | `Dispatch` (或 `Report`) | 滞后的情报消息 |
| 传令兵 | `Messenger` (或 `Courier`) | 携意图 / 战报,可被拦截而丢失 |
| 斥候 | `Scout` | 战略层侦察 |
| 信息年龄 | `InfoAge` | 情报"多久前"的 |
| 幽灵标记 | `GhostMarker` | 超时未更新、褪色为半透明的标记 |
| 兵种 | `Arm` / `UnitType` | 枪 `Spear` / 弓 `Bow` / 骑 `Cavalry` / 盾 `Shield` |
| 士气 | `Morale` | 隐藏关键值,崩则溃逃 |
| 体力 | `Stamina` | 隐藏关键值,竭则战力打折 |
| 伤亡 | `Casualties` | 累积计数器(喂给其他轴) |
| 综合评估值 | `SituationAssessment` | 派生仪表盘(危殆 / 艰难 / 稳健 / 优势) |
| 皇恩 | `ImperialFavor` | 主轴:皇帝的期望与耐心 |
| 粮草 | `Provisions` | 主轴:持续后勤 |
| 经费 | `Funds` (或 `Treasury`) | 主轴:可支配国库 |
| SAN / 心智 | `Sanity` | 主轴:主帅心智,低则认知世界更不可信 |
| 复盘 | `AfterActionReview` (或 `Replay`) | 战后对照回放 |
| 章节 / 战役 | `Chapter` / `Campaign` | 战略层场景 |
| 生涯 | `Career` | 顶层 |

> 命名一律走这张表,保证整个代码库术语一致。新概念入表前先与用户确认译名。
